This page is rendered from the same registry that launch and patch declarations
are checked against. Use the
[JSON registry](../../compatibility/registry.json) and its
[JSON Schema](../../compatibility/schema.json) when another tool needs the
matrix. Every row is exact-certified: `declared` and `verified` identify the
same upstream version set, backed by executable claim files.

The capability column is the probe vocabulary inside `hello.probe`.
`clipped-geometry` and `pointer-hit-grid` remain separate claims. Every
executable exact-version combination is listed in the registry and below.

## What the registry guarantees

The compatibility test fails when a checksummed patch manifest is missing from
the registry, when a package version moves, or when a probe's `ProbeInfo` or
adapter capability declaration no longer matches this data. This prevents the
common failure mode where the documentation promises geometry, annotations or
stable identity that the actual handshake does not announce.

Versions outside an exact certification row are refused. There is no range or
feature-detection fallback that silently upgrades the session contract.
