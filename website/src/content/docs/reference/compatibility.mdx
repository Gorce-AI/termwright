## What the registry guarantees

The compatibility test fails when a required manifest is missing, a T3 artifact
or package version moves, a T1/T2 capability contract is malformed, or a
probe's `ProbeInfo` or adapter capability declaration no longer matches this
data. This prevents the common failure mode where the documentation promises
geometry, annotations or stable identity that the actual handshake does not
announce.

T3 capabilities refuse versions outside their exact certification row. T0–T2
capabilities use compile/capability admission and behavioral conformance; any
missing capability is reported as an explicit degradation, never as a silent
upgrade or a quietly incomplete semantic tree.

Candidate certification also carries a per-stream revision. An unchanged red
candidate stays suppressed at the revision that tested it. When a probe,
runtime bridge, build injection, or certifier changes in a way that can change
that result, maintainers increment only the affected stream revisions. This is
an explicit request to certify those candidates against the new integration,
not a generic retry mechanism.
