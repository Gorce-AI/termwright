## Ten lines, one real terminal

```ts
import {expect, test} from '@termwright/test';

test('asks before running a command', async ({terminal}) => {
  const app = await terminal.launch({command: ['node', 'agent.js']});
  await app.waitForText('Permission required');

  await app.getByRole('button', {name: 'Approve'}).activate();

  await expect(app.getByRole('dialog')).not.toBeVisible();
  await expect(app).toHaveText('running: ls -la');
});
```

Every action goes through the pseudo-terminal: a click is a real mouse report, a
keystroke is real bytes. There is no callback back-channel into the application,
so a test that passes is evidence the program works.

## Three things nobody else has

<CardGrid>
<Card title="Semantic YAML snapshots" icon="document">
The accessibility tree of a terminal app, serialized as reviewable YAML. A snapshot breaks when meaning changes, not when whitespace does, and it matches partially — children you omit are don't-care.

```yaml
- dialog "Permission" [modal]:
    - button "Approve" [focused]
    - button /Rej.*/
```
</Card>
<Card title="Failure forensics" icon="magnifier">
A self-contained HTML report: side-by-side visual diff, a semantic diff in plain sentences (`button "Submit" state changed to disabled`), and an embedded recording positioned on the failing step. Recording is on by default.
</Card>
<Card title="Incremental diffs for agents" icon="seti:robot">
`terminal.capture_since { cursor }` returns the rows **and the semantic subtrees** that changed since a revision, so an agent stops burning context re-reading a screen it has already seen.
</Card>
</CardGrid>

## The assertion nobody writes

A TUI cannot print diagnostics to the screen without corrupting its own render,
so they go to a logger — where a test stops seeing them. termwright follows the
log file, or takes structured records over a public
`termwright:log` channel, and **fails a test that passed while the program
logged an error**. Clicking through a flow while the program logs
`error: failed to save` is not a passing test; it is a test that did not look.

## Honest about what it cannot see

A program without a termwright adapter is still fully testable — text, cells,
colors, modes, scrollback, mouse, paste, resize — and every diagnostic says
`semanticTree: false` rather than inventing roles. Frameworks that compose
strings instead of retaining a widget tree degrade to that generic mode on
purpose, and the [adapter overview](adapters/) says which is which before you
adopt anything.
