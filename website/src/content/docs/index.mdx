## A terminal test

```ts
import {fileURLToPath} from 'node:url';
import {expect, test} from 'termwright/test';

const agent = fileURLToPath(new URL('../agent.js', import.meta.url));

test('approves a command', async ({terminal}) => {
  const app = await terminal.launch({command: [process.execPath, agent]});

  await app.waitForText('Permission required');
  await app.press('Enter');

  await expect(app).toHaveText('running: ls -la');
});
```

The application runs in a real PTY. `press()`, `type()`, resize, and signals use
the same terminal boundary as a person running the program. Semantic pointer
actions are available when an integration can prove the exact recipient.

Semantic locators such as `getByRole()` require a supported framework
integration. Programs without semantics remain testable through
text, cells, keyboard input, snapshots, and process behavior.
Semantics are a progressive enhancement: add an integration when roles, state,
geometry, or exact pointer ownership make a test clearer or safer.

## Core workflows

| Need | Recommended API |
| --- | --- |
| Wait for rendered output | `await app.waitForText('Ready')` |
| Send keyboard input | `await app.press('Enter')` or `await app.type('text')` |
| Find a semantic element | `app.getByRole('button', {name: 'Save'})` |
| Assert a changing UI | `await expect(locator).toBeFocused()` |
| Protect terminal rendering | `await expect(app).toMatchCellSnapshot()` |
| Protect application meaning | `await expect(app).toMatchSemanticSnapshot()` |
| Investigate a failure | Runner replay or a self-contained HTML report |

## Start with the normal workflow

Write repeatable tests with `termwright/test`, run them with the certified
`termwright test` host in CI, and use the same host through Runner while
developing or investigating failures. Add a framework
integration when you need roles, accessible names, state, geometry, or exact
pointer targeting.

Gherkin is available for teams that keep executable feature prose. The
low-level driver is an advanced surface for custom tooling, not the normal test
authoring path.
