# Runner UI review — 7 September 2026

Reviewed on `codex/ui-ergonomics-20260907`, after the inline execution rail,
assertion recording and terminal element picker changes. This is a local UI
review and implementation record, not a published release.

## Coverage and evidence

Reviewed Specs, Runner, replay controls, semantic Tree/properties, Logs, Runs,
Settings and the recorder's start/review flow. Browser checks cover desktop
1440×900 and compact 390×844 views, pointer interaction, keyboard navigation,
empty and loading states, exact run scope, clipboard failures, replay/live
separation and history navigation. Used a retained recording of an actual native
fixture session plus controlled browser fixtures for outcomes, history and logs.
The existing browser suite also covers retries, failures, crash recordings,
source links, recorder save/discard, deep links and offline report boot.

  comparison, tree search/picking and recorder draft restoration.

  associations, semantic comparison and stale draft protection.
- UI build, TypeScript, ESLint, formatting and documentation contract checks passed.
- Inspected captured desktop/mobile layouts after the changes; the filtered

- Manually opened an actual native run’s finalized recording from Runs and
  searched, highlighted and inspected its `approve` element at revision 2.

## Follow-up additions implemented

- **Replay from run history:** exact per-attempt/session recording controls, missing
  archive explanations and replay deep links that survive reload. Correction to
  the initial audit: finalized trace references already exist in the committed
  event journal. The UI now reads them without a manifest schema migration.
- **Semantic tree search:** role/name/test ID/ref matching, ancestor reveal,
  next/previous navigation, pinned highlights and clearing a conflicting filter
  when picking an element directly on the terminal.
- **Attempt comparison:** independent terminal views, matching named step endpoints
  and outcome alignment, individual seek controls, semantic field differences and
  explicit treatment of ambiguous element identities. Desktop and mobile layouts
  were inspected in Chromium.
- **Recorder drafts:** Escape and Keep draft preserve the source; navigation can
  reopen it after a page reload. The destination is editable. Server memory owns
  the draft until save, discard or server exit; stale tabs cannot overwrite or
  discard a newer draft.

## Remaining opportunity

**Inline report semantic history.** Offline reports embed a single semantic
state while terminal frames can be replayed. Full inspection at arbitrary
moments needs retained revision history in the report, rather than reusing a
final tree for earlier frames.

The review did not benchmark very large catalogs or trees and did not certify
other browser engines. All release/publishing work remains separate.
