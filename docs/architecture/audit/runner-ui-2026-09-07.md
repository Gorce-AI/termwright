# Runner UI review — 7 September 2026

Reviewed on `codex/ui-ergonomics-20260907`, after the inline execution rail,
assertion recording and terminal element picker changes. This is a local UI
review and implementation record, not a published release.

## Coverage and evidence

Reviewed Specs, Runner, replay controls, semantic Tree/properties, Logs, Runs,
Settings and the recorder's start/review flow. Browser checks cover desktop
1440×900 and compact 390×844 views, pointer interaction, keyboard navigation,
empty and loading states, exact run scope, clipboard failures, replay/live
separation and history navigation. Used a retained recording of an actual native
fixture session plus controlled browser fixtures for outcomes, history and logs.
The existing browser suite also covers retries, failures, crash recordings,
source links, recorder save/discard, deep links and offline report boot.

## Recommended follow-up, in priority order

1. **Replay from run history.** Persist the finalized trace reference for each exact
   attempt, then expose replay only for recordings that still exist. The current
   native manifest has results/attempts but no trace link. This needs coordinated
   writer/schema/reader work; a UI-only replay button would be misleading.
2. **Search the semantic tree.** Search role, name, test ID and ref; reveal matching
   ancestors, step through matches and preserve selection/highlight. Especially
   useful for large application trees. Keep search separate from terminal picking.
3. **Compare retries.** Open failed and successful attempts at equivalent named
   steps, with a terminal and semantic-state comparison. This depends on reliable
   retained-attempt recording links before it can be a useful history workflow.
4. **Preserve recorder drafts.** Allow returning to a generated test after closing
   its review. Currently Escape follows the discard path. A draft should have an
   explicit lifetime and a distinct discard action.
5. **Inline report semantic history.** Offline reports embed a single semantic
   state while terminal frames can be replayed. Full inspection at arbitrary
   moments needs retained revision history in the report, rather than reusing a
   final tree for earlier frames.

The review did not benchmark very large catalogs or trees and did not certify
other browser engines. All release/publishing work remains separate.
